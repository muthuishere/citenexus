CiteNexus makes one promise: **no ungrounded claim.** Not "zero hallucination" —
we won't pretend the model never errs. We guarantee it never *asserts what the
evidence doesn't support*. Three steps stand between a question and an answer you
can defend.

## Ground → verify → cite or abstain

1. **Ground.** The answer is generated at temperature 0 from retrieved passages
   only. The answer is written in the language you asked for; the **quote stays
   verbatim in the source's own language**, so an English answer can carry a
   Telugu citation.
2. **Verify.** A grounding gate runs **per atomic claim**. Anything unsupported
   is dropped before it reaches you — see the mechanism below, or
   [the faithfulness gate](/citenexus/faithfulness/) for the full story of what
   the old predicate let through.
3. **Cite or abstain.** A surviving claim resolves to a document, a page, and the
   verbatim passage. If nothing supports the question, CiteNexus emits the single
   **pinned refusal string** — identical in every port — rather than guessing.

Those three steps sit inside a longer pipeline — retrieve, fuse, rerank, ground,
apply the authority floor, check for conflicts, then generate and gate. For where
each stage runs and which module implements it, see
[How it works](/citenexus/architecture/).

## What "verified" actually checks

The gate is **not** a bag-of-words check, and the difference is the whole
guarantee. Set containment — "every word of the claim appears somewhere in the
passage" — is closed under two meaning-changing edits:

- **Reordering.** *"The Customer shall indemnify the Supplier"* and *"The
  Supplier shall indemnify the Customer"* are the same token set and opposite
  obligations.
- **Deletion.** `not` is just a token, so dropping a negation yields a strict
  subset — and passes.

Measured in `spikes/library-stress/`: that predicate accepted **9 of 9**
deliberately false answers. What ships instead (ADR-0009) requires:

1. the claim's tokens to appear in the passage **in order**, preserving
   multiplicity, within a **bounded interior gap**; and
2. every **polarity marker** inside the matched span to survive into the claim —
   drop one of two negations and it is rejected.

It is strictly narrower than the old predicate: anything it accepts, the old one
accepted too, so it can only reduce what passes. Its cost is over-refusal, not
under-refusal.

<Aside type="caution" title="The gap budget is pinned, and it was fitted on English">
The interior-gap budget is `MAX_SINGLE_GAP = 4`, `MAX_TOTAL_GAP = 8`
(`answer/verify.py:135-136`). It is **not configurable** — a caller who widens it
silently weakens the guarantee, and a conformance vector cannot pin a value the
caller controls. The swept knee was `(3, 6)`; `(4, 8)` leaves headroom for
compressed answers.

**That sweep ran on synthetic English fixtures.** The same is true of conflict
detection's thresholds (`MAX_RESIDUAL = 1` and its companions in
`answer/conflict.py`). The attacks the budget defends against fail on *order*,
not on gap size, so the constants are not load-bearing for those — but if you are
tuning for a non-English corpus, know that nobody has fitted these for one, and
we cannot tell you what the right value is there. Measure over-refusal on your
own corpus before you trust the recall number.
</Aside>

<Aside type="note" title="The pinned refusal">
Every port emits the exact same sentence when it abstains:
*"I can't answer that from the available evidence."* It is a fixed constant, not
a generated apology — so a refusal is always recognizable and never a stealth
hallucination.
</Aside>

## The pinned algorithms are byte-for-byte identical

The deterministic pieces aren't re-implemented per language and hoped to match —
they're pinned by a shared [`conformance/`](https://github.com/muthuishere/citenexus/tree/main/conformance)
suite of golden vectors. Tokenization (v1 and v2), BM25, RRF, the chunker, the
language-fallback chain, EU-id derivation and the frozen gate predicate produce
identical bytes in Go, JavaScript and Python, and the hermetic `ask()` demo below
produces the same decision, answer and cited passage in all three.

<Aside type="caution" title="The ports gate the whole answer; Python gates each claim">
The ordered/polarity predicate ships in all three languages and all three answer
paths now call it. The remaining difference is granularity: Python splits a
generated answer into atomic claims and verifies each one, keeping the supported
ones and counting the rest in `unsupported_claims_removed`. Go and JavaScript
apply the predicate to the **whole answer as a single claim**, so a multi-claim
answer there is all-or-nothing — it cannot come back trimmed. The old v1
set-containment predicate stays exported in both ports, frozen for the
conformance vectors, and is no longer what `ask()` calls.
</Aside>

## Navigate, don't cite

Higher-level structure — graph and wiki — is **navigation over evidence**, never
a citation itself. Every hit resolves *down* to a cited Evidence Unit before an
answer is generated. You can browse the map, but the answer is always anchored to
a real passage.

What this protects is the **content** of a citation, not the topology of the
graph: an edge or a wiki link is a route to evidence, and is never itself quoted
as a fact.
