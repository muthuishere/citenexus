import { Aside, Tabs, TabItem } from '@astrojs/starlight/components';

**The failure this prevents:** your corpus holds a filing and its restatement, or
a 2019 policy and its 2026 replacement. Both are real, both are indexed, both are
grounded. Whichever one happens to rank first becomes the answer — and nothing
tells the caller the other one exists.

That is not hypothetical. Before conflict detection existed, the corpus below
returned a confident, correctly-cited answer with `conflicts_detected = 0`.
Python abstains on it now; **Go and JavaScript still answer**, and their tabs
show exactly that:

<Tabs syncKey="lang">
<TabItem label="Python">
```python
rag.ingest(text="The dividend for the period was 12 cents per share.",
           document_id="filing-q1")
rag.ingest(text="The dividend for the period was 30 cents per share.",
           document_id="filing-q1-restated")

response = rag.ask("What was the dividend per share for the period?")

print(response.evidence.decision)            # refused
print(response.answer)
print(response.conflicts)

for src in response.sources:                 # BOTH sides are cited
    print(src.document, "—", src.passage)
```

```text
refused
The available evidence disagrees, so I can't answer that.
('value: filing-q1-restated vs filing-q1 (30 vs 12)',)
filing-q1-restated — The dividend for the period was 30 cents per share.
filing-q1 — The dividend for the period was 12 cents per share.
```

In `strict` mode an unresolved conflict that touches the answer's own claim is an
**abstention with both sides cited**. "These sources disagree, here is each of
them" is a defensible output. Silently picking one is not.
</TabItem>
<TabItem label="Go">
**Conflict detection does not exist in this port.** Go declares `conflicts` and
`conflicts_detected` for wire parity and implements no detection, so on this
corpus it does the thing the page opens by warning about: it answers, from
whichever side ranked first. That is worth seeing rather than being told.

```go
package main

import (
	"fmt"

	"github.com/muthuishere/citenexus/golang/answer"
)

func main() {
	corpus := []answer.Doc{
		{DocumentID: "filing-q1", Text: "The dividend for the period was 12 cents per share."},
		{DocumentID: "filing-q1-restated", Text: "The dividend for the period was 30 cents per share."},
	}

	res := answer.Ask(corpus, "What was the dividend for the period?", answer.DefaultTopK)

	fmt.Println(res.Evidence.Decision)          // answered  <- Python refuses here
	fmt.Println(res.Answer)                     // one side, quoted verbatim
	fmt.Println(res.Evidence.ConflictsDetected) // 0 — no detection in this port
	fmt.Println(res.Sources[0].Document)
}
```

```text
answered
The dividend for the period was 12 cents per share.
0
filing-q1
```

What Go **does** give you on the same corpus is the rest of the guarantee: the
answer is verbatim from a real document, it passed the faithfulness gate, and an
unsupported question still refuses. What it cannot tell you is that the other
filing exists. Until detection lands here, compare `Evidence.DistinctDocuments`
yourself, or run conflict-sensitive corpora through Python.
</TabItem>

This is the one refusal that does *not* emit the pinned refusal string — it says
*"The available evidence disagrees, so I can't answer that."* and
`evidence.conflicts_detected` is above zero. That pair is how you tell it apart
from the other five ways `ask()` can refuse:

## Choosing how much to enforce

<Tabs syncKey="lang">
<TabItem label="Python">
```python
from citenexus.domain.trust import TrustMode

rag.ask(q, mode=TrustMode.strict)        # conflict on the claim -> abstain, cite both
rag.ask(q, mode=TrustMode.normal)        # answer, but surface the conflict
rag.ask(q, mode=TrustMode.exploratory)   # record only
```
</TabItem>
<TabItem label="Go">
There is **one mode in this port and it is `strict`** — `result.TrustModeStrict`
is the only `TrustMode` constant Go defines, and `Ask` takes no mode argument.
With no conflict detection there is nothing for `normal` to surface, so the knob
would be decoration.
</TabItem>
<TabItem label="JavaScript">
There is **one mode in this port and it is `strict`** — `TrustMode` exports the
single value `"strict"`, and `ask` takes no mode argument. With no conflict
detection there is nothing for `normal` to surface.
</TabItem>
</Tabs>

Use `strict` where a wrong answer is worse than none. Use `normal` when a human
reads every answer anyway and wants the flag, not the block.

## Detection is deterministic, and it never resolves

No model is involved. Detection runs over already-grounded candidates using
content-derived signals only, across an otherwise-shared token set. There are
exactly three rules, tried in order:

1. **Antonym pair** — one content word on each side forms a known antonym pair
   (`permitted`/`prohibited`, `required`/`optional`, …).
2. **Negation parity** — the two passages differ in the *parity* of their
   negations. A negation that is reported speech ("the vendor claimed it was
   not…") is excluded: it belongs to a third party, not to the source.
3. **Numeric-value divergence** — the measured values differ, the units match,
   and neither set is a superset of the other (an elaboration is not a conflict).
   **Dates participate only when they read as digit-leading numbers** (`2019`);
   there is no date rule as such, and no date parsing.

<Aside type="caution" title="Why the golden vectors exist anyway">
The golden vectors are published (`conformance/cases/conflict.json`) precisely so
the ports can be held to them when detection lands — the run above in the Go and
JavaScript tabs is what "no detection" looks like today.
</Aside>

It deliberately **does not resolve**. Deciding *which* of two contradictory
sources wins is a policy question about authority, recency and jurisdiction. That
belongs to you, not to a retrieval library.

<Aside type="caution" title="Why the false-positive rate is the number that matters">
In strict mode a detected conflict causes an abstention, so a **false** conflict
is a **false refusal** — the library becomes useless long before it becomes
wrong. Detection is therefore tuned against hard negatives: passages that look
contradictory but are not (a dose for adults vs one for children, p50 vs p99
latency, staging vs production). Measured: **0 false positives** across 27 hard
negatives and 10 held-out cases, in five unrelated domains independently — on
**synthetic English** fixtures. That is the honest scope of the number.
</Aside>

## Where the thresholds came from — and why you can't turn them

Every constant below is **pinned in the source and exposed as no caller
parameter**. That is deliberate: a conformance vector cannot pin a value the
caller controls, and each one trades directly against false abstention.

| Constant | Value | What it governs |
|---|---|---|
| `MAX_RESIDUAL` | `1` | content divergence still allowed *after* removing the polarity signal itself |
| `SUBJECT_OVERLAP` | `0.60` | overlap needed before two passages count as being about the same subject |
| `MAX_SYMDIFF` | `3` | total divergence past which the pair is simply unrelated |
| `MIN_CONTENT` | `3` | passages with fewer content tokens are not comparable |
| `DUPLICATE_JACCARD` | `0.80` | where two same-polarity passages become surface clones |
| `CONFLICT_TOP_K` | `6` | how many post-fusion candidates are compared pairwise |

`MAX_RESIDUAL` does nearly all the work, and the ADR-0007 sweep shows why it is
frozen at 1: relaxing it to 2 buys 4 points of recall (0.89 → 0.93) and costs
**15 points of false-conflict rate** (0.00 → 0.15) — in strict mode, 15 points of
false *refusal*.

<Aside type="caution" title="These were swept on synthetic English sentences">
The sweep that produced every value above ran on **synthetic English** fixtures.
They have never been fitted against a non-English corpus, and nothing in the
library adapts them to one. If you run a non-English or heavily domain-specific
corpus in `strict` mode, treat the false-refusal rate as **unmeasured for your
data** and measure it yourself before trusting the abstention behaviour.
</Aside>

## Duplicates stop inflating your confidence

The same comparison, inverted, catches near-duplicates. One sentence mirrored
across five document IDs used to report `distinct_documents = 5` — five
independent confirmations of a fact that had exactly one source.

<Tabs syncKey="lang">
<TabItem label="Python">
```python
response.evidence.distinct_documents   # 1, not 5
response.evidence.supporting_sources   # 1
```
</TabItem>
<TabItem label="Go">
Duplicate collapsing rides on the same comparison as conflict detection, so it is
**Python-only too**. On five mirrored documents Go reports
`Evidence.DistinctDocuments == 5` — five counts of one fact. Deduplicate the
`[]answer.Doc` slice yourself before you pass it in.
</TabItem>
<TabItem label="JavaScript">
Duplicate collapsing is **Python-only**, for the same reason as conflict
detection. Five mirrored documents give `evidence.distinct_documents === 5` here.
Deduplicate the corpus array before passing it to `ask`.
</TabItem>
</Tabs>

This claims **surface clones only**. Telling a genuinely independent restatement
apart from a paraphrase of the same origin is not decidable from text —
independence is a fact about provenance — so the rule is biased to
under-collapse. Two sources it keeps separate may still share an origin.
