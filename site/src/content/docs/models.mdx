CiteNexus bundles **no models**. Embedding, LLM, and optionally a reranker and a
vision model for figures are injected by you. The shipped clients speak the
OpenAI API — nothing runs locally that you didn't wire up, and the key stays in
your endpoint config.

## The two clients every port ships

Embedding and chat generation are the seams all three ports consume, so all three
ship a client for them. Same endpoint, same `${ENV}` header convention, one tab
per language:

<Tabs syncKey="lang">
<TabItem label="Python">
```python
from citenexus import OpenAICompatibleEmbedding, OpenAICompatibleGenerator

embedder = OpenAICompatibleEmbedding(base_url="…/v1", model="bge-m3")
generator = OpenAICompatibleGenerator(base_url="…/v1", model="qwen2.5")
```
</TabItem>
<TabItem label="Go">
```go
import "github.com/muthuishere/citenexus/golang/models"

// A real net/http transport; timeout 0 means the 60s default.
http := models.NewHTTPClient(nil, 0)

embedder := models.NewOpenAIEmbedding("…/v1", "bge-m3", http.Transport())
generator := models.NewOpenAIChatGenerator(
    "…/v1", "qwen2.5",
    0.0, nil, // temperature, max_tokens (nil → omitted from the request)
    http.Transport(),
)
```
</TabItem>
<TabItem label="JavaScript">
```ts
import { HttpClient, OpenAIChatGenerator, OpenAIEmbedder } from "@muthuishere/citenexus";

const http = new HttpClient();
const send = (url: string, body: string, headers: Record<string, string>) =>
  http.send(url, body, headers);

const embedder = new OpenAIEmbedder({ base_url: "…/v1", model: "bge-m3" }, send);
const generator = new OpenAIChatGenerator({ base_url: "…/v1", model: "qwen2.5" }, send);
```
</TabItem>
</Tabs>

Auth on all three — `${ENV}` templates expanded at the request boundary, never
stored — is in [Custom endpoints & auth](/citenexus/custom-endpoints/).

## Reranker and vision, and wiring it all up

The other two shipped clients, and the `CiteNexus(...)` constructor that consumes
them, are Python. All four Python clients import from the top-level package and
share one constructor shape (keyword-only `base_url`, `model`, `transport`,
`headers`, plus role-specific extras):

```python
from citenexus import (
    CiteNexus,
    OpenAICompatibleEmbedding,
    OpenAICompatibleGenerator,
    OpenAICompatibleReranker,
    OpenAICompatibleVision,
)

rag = CiteNexus(
    "./citenexus-data",
    embedder=OpenAICompatibleEmbedding(base_url="…/v1", model="bge-m3"),
    generator=OpenAICompatibleGenerator(base_url="…/v1", model="qwen2.5"),
    vision=OpenAICompatibleVision(base_url="…/v1", model="qwen2.5-vl"),   # figures → cited evidence
)
```

<FacadeNote title="Python only — and for a reason, not an oversight">
	<p>
		Neither port has a reranker or vision client, because neither has a caller for one: there is
		no retrieval layer to reorder and no figure Evidence Unit to describe, so a published client
		would promise a capability that does not exist. The same goes for the
		<code>CiteNexus(...)</code> wiring — it takes a store URI, and Python is the only port with a
		store.
	</p>
</FacadeNote>

Any endpoint that speaks the OpenAI API works — Ollama, OpenAI, a local vLLM or
llama.cpp server, or Gemini's OpenAI-compatibility endpoint. The two shipped
examples (`examples/multilingual` and `examples/law-authority`) run on **hosted
Jina + Gemini**, which is the cheap default stack. For an all-local run,
`task local:ollama:up` pulls the Ollama variant — `bge-m3`, `qwen2.5`, and the
reranker `xitao/bge-reranker-v2-m3` (note the `xitao/` prefix).

<Aside type="tip" title="An endpoint is one option, not the requirement">
The model seam is a **published contract**, not a URL. `base_url`, `headers` and
`transport` are constructor parameters of *these* clients — they appear in no
contract method — so an in-process model, a mock, or a cached fixture satisfies
the same seam without opening a socket. The shipped clients above are ordinary
providers with no privileges. See
[Provider contracts](/citenexus/providers/).
</Aside>

<Aside type="note" title="Vision is host-fulfilled">
The vision model is called through a two-phase seam: the core emits a description
*request*, your host fulfills it against the endpoint, and the description is
assembled back into a cited figure Evidence Unit. The core never holds your API
key.
</Aside>
